# 第六章：流式输出与记忆管理

## 6.1 流式输出 — 像打字机一样逐字显示

### 为什么需要流式？

平时用 ChatGPT 网页版，回答是一个字一个字蹦出来的。如果等 10 秒钟一次性出完整回答，你会觉得卡。流式输出就是**生成一个字就显示一个字**，体验更好。

### 基础用法

```python
from langchain_deepseek import ChatDeepSeek
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

llm = ChatDeepSeek(model="deepseek-chat", streaming=True)
prompt = ChatPromptTemplate.from_template("写一首关于{topic}的诗")
chain = prompt | llm | StrOutputParser()

# stream() 返回一个生成器，每次 yield 一小段文本
for chunk in chain.stream({"topic": "春天"}):
    print(chunk, end="", flush=True)
    # end=""   → 不换行
    # flush=True → 立刻显示，不等缓冲区满了再刷
```

输出效果：
```
春 天 来 了 ， 花 儿 开 了 ...（一个字一个字往外蹦）
```

### 异步流式

做 Web 服务时用异步版本：

```python
async for chunk in chain.astream({"topic": "秋天"}):
    print(chunk, end="", flush=True)
```

### FastAPI 集成示例（选学）

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from langchain_deepseek import ChatDeepSeek
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

app = FastAPI()

chain = (
    ChatPromptTemplate.from_template("解释：{topic}")
    | ChatDeepSeek(model="deepseek-chat", streaming=True)
    | StrOutputParser()
)

@app.get("/stream")
async def stream(topic: str):
    """把 LangChain 流式输出包装成 HTTP 接口"""
    async def generate():
        async for chunk in chain.astream({"topic": topic}):
            yield chunk
    return StreamingResponse(generate(), media_type="text/plain")

# 启动：uvicorn main:app --reload
# 浏览器访问：http://localhost:8000/stream?topic=机器学习
```

> 上面这段需要装 fastapi 和 uvicorn，本项目已经装好了。

## 6.2 Memory（记忆）— 让模型记住刚才聊了什么

### 问题

默认情况下，每次调用模型都是"失忆"的：

```
你：我叫小明。
模型：你好小明！

你：我叫什么名字？
模型：？？？（不知道，因为每次对话都是独立请求）
```

### 解决方案：RunnableWithMessageHistory

```python
from langchain_core.runnables.history import RunnableWithMessageHistory
from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_deepseek import ChatDeepSeek

# 用字典存所有用户的聊天记录
# 生产环境要换成 Redis 或数据库，否则重启就没了
store = {}

def get_session_history(session_id: str):
    """根据 session_id 找到该用户的聊天历史"""
    if session_id not in store:
        store[session_id] = InMemoryChatMessageHistory()
    return store[session_id]

# 提示词里要留一个 MessagesPlaceholder，历史消息就插到这里
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个友好的助手。"),
    MessagesPlaceholder(variable_name="history"),  # ← 聊天记录插这里
    ("human", "{input}")                            # ← 当前的问题
])

llm = ChatDeepSeek(model="deepseek-chat")
chain = prompt | llm

# 套上"记忆外壳"
chain_with_memory = RunnableWithMessageHistory(
    chain,                         # 要加记忆的链
    get_session_history,           # 获取历史的函数
    input_messages_key="input",    # 输入中哪个字段是用户消息
    history_messages_key="history" # 提示词中哪个字段放历史
)

# 第一次对话
response1 = chain_with_memory.invoke(
    {"input": "我叫小明，我喜欢编程。"},
    config={"configurable": {"session_id": "user-001"}}
)
print(response1.content)  # "你好小明！编程很有趣！"

# 第二次对话——它能记住！
response2 = chain_with_memory.invoke(
    {"input": "我叫什么名字？我的爱好是什么？"},
    config={"configurable": {"session_id": "user-001"}}
)
print(response2.content)  # "你叫小明，你喜欢编程。"

# 注意：session_id 必须一样，不同 session_id 之间的记忆是隔离的
```

### 参数详解

| 参数 | 说明 |
|---|---|
| `get_session_history` | 函数，输入 session_id，返回该 session 的历史记录 |
| `input_messages_key` | 你的输入字典里，哪个 key 对应的问题（上例是 `"input"`） |
| `history_messages_key` | 提示词模板里，`MessagesPlaceholder` 的变量名（上例是 `"history"`） |

> 带记忆和不带记忆的区别：带记忆的调用时多了 `config={"configurable": {"session_id": "xxx"}}`。

### 生产环境：存到数据库

```python
from langchain_community.chat_message_histories import SQLChatMessageHistory

def get_session_history(session_id: str):
    return SQLChatMessageHistory(
        session_id=session_id,
        connection="sqlite:///chat_history.db"  # 存到 SQLite
    )
```

## 6.3 本章小结

- **流式输出**：`.stream()` / `.astream()`，一个字一个字出，体验好
- **记忆管理**：`RunnableWithMessageHistory` 给链套上记忆
- 记忆的关键：prompt 里加 `MessagesPlaceholder`，调用时传 `session_id`
- 生产环境别用内存存历史，用数据库
